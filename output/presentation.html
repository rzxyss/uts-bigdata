Demonstrasi 5 Karakteristik Big Data (Table 3.1 & 5.1)

Evaluasi konseptual dan implementasi teknis pada surveilans COVID-19 Indonesia

1. VOLUME M1, M2, M5, M6

Pencatatan longitudinal multi-tahun kasus baru, rawat inap, kematian, dan kapasitas faskes di 34 provinsi selama 730 hari.

Bukti: 25.300 baris, 7.94 MB heap uncompressed, chunking batch pandas & RDD parallel partitions.
2. VELOCITY M1, M2, M5, M6

Frekuensi pelaporan data harian berkala dari dinas kesehatan daerah dan simulasi streaming micro-batch untuk sistem peringatan dini.

Bukti: Latensi ingestion 1.25 – 2.37 ms per batch wilayah, throughput pemrosesan stabil.
3. VARIETY M3, M4

Penggabungan data tabular terstruktur (CSV kasus), hierarki semi-terstruktur (JSON faskes ICU), dan biner kolumnar (Parquet sensus BPS).

Bukti: 3 skema data berbeda di-flattening dan di-join tanpa kehilangan integritas skema.
4. VERACITY M3, M4, M7

Pembersihan anomali nyata di lapangan: duplikasi baris, revisi kasus negatif oleh RS, inkonsistensi huruf kapital, dan missing tes PCR.

Bukti: 25.300 baris mentah dibersihkan menjadi 24.820 baris valid; 480 duplikat disaring.
5. VALUE M7 (SC3)

Mengekstrak informasi kesehatan publik: penentuan 7-day rolling incidence rate per 100k populasi, deteksi puncak gelombang Delta vs Omicron, korelasi proteksi vaksinasi booster terhadap penurunan Case Fatality Rate (CFR), dan evaluasi keterisian tempat tidur ICU (Bed Occupancy Rate - BOR).

Bukti: Terbukti provinsi dengan cakupan booster >45% memiliki CFR <2.35% dan terhindar dari saturasi fatal tempat tidur ICU.

Alur integrasi data dari sumber faskes ke National Public Health Intelligence System

|                                 BIG DATA PIPELINE ARCHITECTURE                                    |
+---------------------------------------------------------------------------------------------------+
  [DATA SOURCES]             [INGESTION LAYER]               [STORAGE LAYER]         [PROCESSING]
  1. RS Rujukan (CSV)   -->  Daily Batch Collector      -->  HDFS Storage Lake  -->  Apache Spark
  2. Kemenkes (JSON)    -->  Simulated Streaming Batch  -->  Parquet (Snappy)   -->  Spark SQL
  3. BPS Sensus (Parq)  -->  Data Quality Gate (Veracity)    Partition Layout        Catalyst Engine
+---------------------------------------------------------------------------------------------------+
  [SERVING & ANALYTICS LAYER]
  -> Spark SQL Temporary Views ('cases', 'vaccines', 'demographics')
  -> Window Functions (7-Day Rolling Incidence per 100k Population)
  -> Interactive Dashboards & Public Health Alerts

Segmen 1: Mahasiswa 1 (Project Lead / Analyst) — Modul M1 (SC1) 00:00 – 00:45 (45 Detik)

"Halo semua. Saya [Nama], Project Lead kelompok kami. Dalam ETS Big Data kali ini, kami mengangkat studi kasus COVID-19 Epidemiological Analytics di 34 provinsi Indonesia periode 2021 hingga 2022. Masalah utama yang dihadapi otoritas kesehatan publik adalah bagaimana mengolah lonjakan puluhan ribu data pelaporan harian dari faskes daerah, memantau risiko kejenuhan tempat tidur ICU rumah sakit rujukan, dan mengukur efektivitas program vaksinasi secara akurat. Melalui kacamata 5Vs Big Data, kami mengelola Volume berupa 25.300 rekam data longitudinal, Velocity dari pelaporan harian faskes, Variety yang menggabungkan CSV kasus, JSON fasilitas ICU, dan Parquet demografi BPS, Veracity dalam membersihkan duplikasi dan anomali nilai negatif, serta Value untuk intervensi tanggap darurat epidemiologi."

Segmen 2: Mahasiswa 2 (System Engineer) — Modul M2 (SC1) 00:45 – 01:30 (45 Detik)

"Saya [Nama], System Engineer. Arsitektur Big Data yang kami terapkan mengadopsi model Lambda Architecture. Di lapisan Batch Layer, data historis disimpan dalam format terkompresi Parquet pada simulasi HDFS dan diproses berkala oleh Apache Spark. Di lapisan Speed Layer, kami mendemonstrasikan aspek Velocity melalui ingestion micro-batches harian dari dinas kesehatan provinsi. Pada layar terminal, dapat kita saksikan simulasi kedatangan 5 batch harian dengan rata-rata latensi ingestion hanya 1,5 hingga 2 milidetik per batch wilayah. Arsitektur ini menjamin ketersediaan data real-time untuk early-warning system sekaligus menjaga konsistensi analitik data historis skala besar pada serving layer."

Segmen 3: Mahasiswa 3 (Data Engineer) — Modul M3 & M4 (SC2) 01:30 – 02:30 (60 Detik)

"Saya [Nama], Data Engineer. Menjawab aspek Variety dan Veracity dari Modul 3 dan 4, sistem kami mengintegrasikan 3 format berbeda: CSV kasus harian berukuran 1,77 MB, JSON bertingkat untuk fasilitas ICU dan vaksinasi berukuran 23,8 KB, serta Parquet demografi BPS berukuran 9,9 KB. Seperti yang terlihat pada benchmark, format kolumnar Parquet menghasilkan efisiensi penyimpanan tertinggi dan mendukung column pruning yang jauh lebih cepat dibandingkan scanning baris pada CSV. Untuk aspek Veracity, data mentah sengaja kami uji dengan anomali nyata: ditemukan 480 baris duplikat identik, 81 data kasus bernilai negatif akibat koreksi pelaporan manual, dan 1.528 missing values pada tes PCR. Menggunakan PySpark DataFrame cleaning, seluruh duplikat disaring, teks distandarisasi, dan anomali negatif dinetralkan, menghasilkan 24.820 rekam data terkurasi yang valid."

Segmen 4: Mahasiswa 4 (Big Data Developer) — Modul M5 & M6 (SC3) 02:30 – 03:45 (75 Detik)

"Saya [Nama], Big Data Developer. Pada Modul 5 dan 6, kami mendemonstrasikan dua mesin pemrosesan terdistribusi: Hadoop MapReduce dan Apache Spark Core. Pertama, pada Hadoop Streaming Python, skrip Mapper kami memetakan 25.168 pasangan key-value berdasarkan kelompok kepulauan, Combiner mereduksi data lokal jaringan, dan Reducer menjumlahkan total kasus serta mortalitas. Kedua, kami mengimplementasikan Apache Spark RDD. Melalui mekanisme lazy evaluation, transformasi map dan reduceByKey membentuk graf asiklik terarah (DAG) yang dieksekusi secara in-memory begitu aksi collect dipanggil. Spark RDD menyelesaikan komputasi terdistribusi dalam waktu 3,8 detik pada executor lokal, membuktikan keunggulan pemrosesan in-memory Spark atas I/O disk konvensional."

Dari visualisasi kurva epidemiologi, kita dapat membedakan dengan jelas Gelombang Delta dengan mortalitas dan keterisian ICU tinggi, serta Gelombang Omicron dengan lonjakan kasus masif namun fatalitas lebih rendah. Pada grafik scatter, terbukti secara saintifik bahwa provinsi dengan cakupan vaksin booster di atas 45% memiliki Case Fatality Rate yang secara signifikan lebih rendah di bawah 2,35%. Terakhir, kami membuktikan Tabel 8.2: Operasi B dengan multi-join dan windowing memerlukan waktu 778 milidetik, lebih kompleks dibanding Operasi A agregasi tunggal sebesar 606 milidetik. Kesimpulannya, pipeline Big Data ini berhasil menjawab pertanyaan utama penugasan dan memberikan wawasan krusial bagi penanganan pandemi. Terima kasih."
